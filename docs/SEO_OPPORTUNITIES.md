# SEO Opportunities

Review date: 12 October 2026

## Current foundation

AutoHisab has server-rendered explanatory content, unique titles and descriptions, self-referencing canonicals, consistent Open Graph URLs, crawlable internal links, a complete sitemap, permissive robots rules, and an HTTPS production origin. Example prices are explicitly labelled as illustrative rather than current market claims.

## Prioritised opportunities

### 1. Establish measured search demand

After Search Console verification, group queries by intent: fuel cost calculation, fuel average education, monthly petrol budgeting, petrol-versus-hybrid comparison, and total ownership cost. Use impressions and position data to improve pages that already match demand before creating new URLs.

### 2. Improve snippets from evidence

Review high-impression, low-click pages after enough data accumulates. Test clearer titles and descriptions that match the page's actual calculation or guide content. Keep Pakistan, PKR, km/L, calculator type, and the non-live-price distinction where relevant; avoid unsupported “best,” “accurate,” or current-price claims.

### 3. Strengthen topical paths

Add only original pages with distinct user intent. Candidate topics include interpreting dashboard fuel averages, budgeting for motorway versus city driving, ownership-cost sensitivity scenarios, and a documented financing model if product scope later approves it. Do not create thin city/model permutations or pages that repeat the same formula with swapped keywords.

### 4. Add structured data selectively

Consider `WebSite` and `BreadcrumbList` markup when visible site structure supports it. Consider `WebApplication` only after checking that all required/recommended properties are truthful. Do not add ratings, reviews, prices, FAQs, or product availability that the page does not visibly and verifiably provide.

### 5. Improve internal discovery

Use Search Console landing/query data to add contextual links between the exact guide section and relevant calculator state. Keep descriptive anchor text and avoid site-wide keyword repetition. A future guides index may help discovery once enough distinct guides exist.

### 6. Monitor technical quality

Track Core Web Vitals and indexing after releases. Investigate only reproducible issues, paying attention to client-side calculator hydration, font loading, mobile layout stability, and accidental canonical-origin drift. Preserve the current static rendering of primary content.

## Not recommended now

- Publishing live petrol prices without an authoritative, maintained source and visible update timestamp.
- Programmatic model/city pages with near-duplicate text.
- Claiming savings, accuracy, or market values from illustrative defaults.
- Adding structured data solely to pursue rich results.
- Changing URLs that already have impressions without a redirect and migration plan.

## Success measures

Use non-branded impressions, qualified organic clicks, calculator engagement after organic landing, indexed-versus-submitted URLs, and Core Web Vitals. Measure changes over comparable periods and annotate deployments; rankings alone are too volatile to prove a release caused an outcome.
